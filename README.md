# butschster/tui-desktop

Оконный менеджер для терминала на рантайме Wippy.

Один процесс-композитор владеет физическим экраном и рисует окна; каждое окно —
отдельный процесс, который пишет в собственный viewport через обычный `tty` и
считает, что владеет терминалом целиком. Ни одно окно не знает, что оно окно:
поэтому в окне работает настоящий `bash`, `htop`, редактор или Claude Code —
без единой строчки, написанной под этот десктоп.

Тем же экраном одновременно управляет агент: у модуля есть HTTP-канал, которым
можно открыть окно, переставить его, напечатать в него и **прочитать его экран**.

```
физический TTY → surface композитора → viewport → процесс окна → PTY-прокси → программа
```

## Что нужно

- Wippy **0.3.40a** или новее — модуль `tty` появился там (#631, фиксы в #637).
- Приложение Kickside, дающее `app:api` (роутер с аутентификацией).

## Запуск

```bash
wippy run --host butschster.tui_desktop:terminal desktop
```

`--host` здесь обязателен, и это не придирка: автодетект терминального хоста в
CLI — просто подсчёт записей `terminal.host` во всём реестре, а этот модуль
приносит вторую. С момента установки **каждая** команда приложения требует
явного `--host`; соседние команды выбирают хост приложения
(`--host wippy.terminal:host`).

Собственный хост нужен ради `hide_logs`. Диффер поверхности считает себя
единственным писателем в терминал, поэтому строка лога разъезжает кадр
насовсем — неизменившиеся строки не перерисовываются. Забрать под это хост
приложения нельзя: на нём живут фоновые процессы, и приложение лишилось бы лога.

### Клавиши

- `alt+n` — новое окно с интерактивным bash
- `alt+o` — меню окон, которые объявило приложение
- `alt+w` — закрыть текущее окно
- `alt+m` — свернуть текущее окно
- `alt+tab` — следующее окно
- `alt+1`…`alt+9` — окно по номеру из полосы сверху
- `ctrl+q` — закрыть все окна и выйти

Всё остальное уходит внутрь окна. Акселераторы держатся на `alt` нарочно:
`ctrl` и `tab` слишком часто нужны самим программам, и красть их — значит
ломать редактор внутри.

Мышью можно перетащить окно за заголовок, потянуть за правый нижний угол,
нажать `[-]`, `[□]`, `[×]` и переключиться по вкладке сверху. Включённая мышь
забирает у терминала обычное выделение текста — для копирования держите Shift.

## Командный канал

Все ручки живут за аутентифицированным роутером приложения.

- `GET /tui-desktop/windows` — открытые окна, фокус, размер экрана
- `POST /tui-desktop/windows` — открыть окно: `entry`, `command`, `title`, `x`, `y`, `w`, `h`
- `POST /tui-desktop/windows/{id}/type` — напечатать `text`, при `enter: true` с переводом строки
- `POST /tui-desktop/windows/{id}/key` — одна клавиша: `key`, `ctrl`, `alt`, `shift`
- `POST /tui-desktop/windows/{id}/screen` — содержимое окна строками
- `POST /tui-desktop/windows/{id}/move` — переставить: `x`, `y`
- `POST /tui-desktop/windows/{id}/resize` — размер: `w`, `h`
- `POST /tui-desktop/windows/{id}/focus` — поднять наверх
- `POST /tui-desktop/windows/{id}/minimize` — свернуть или развернуть: `value`
- `POST /tui-desktop/windows/{id}/close` — закрыть

Мастерская — окна, собранные на ходу:

- `POST /tui-desktop/apps` — собрать окно: `name`, `source`, `title`, `width`, `height`, `modules`
- `GET /tui-desktop/apps` — сохранённые окна и признак `live` (есть ли запись в реестре сейчас)
- `DELETE /tui-desktop/apps/{name}` — убрать окно из хранилища и реестра

Префикс пути задаёт роутер приложения, а не модуль: `/api/v1` на стенде
kickside, `/api` в харнессе. Промах отдаёт страницу фасада с кодом 200, поэтому
проверять стоит по `content-type`, а не по коду.

```bash
curl -X POST -H 'Content-Type: application/json' \
  -d '{"title":"сборка","command":"/bin/bash --noprofile --norc"}' \
  http://localhost:8099/api/v1/tui-desktop/windows

curl -X POST -H 'Content-Type: application/json' \
  -d '{"text":"make test","enter":true}' \
  http://localhost:8099/api/v1/tui-desktop/windows/w1/type

curl -X POST -H 'Content-Type: application/json' -d '{}' \
  http://localhost:8099/api/v1/tui-desktop/windows/w1/screen
```

Команды без ответа не бывает: молчание композитора невозможно отличить от
применённой команды, и вызывающий поверил бы в успех. Незапущенный десктоп и
неотвечающий десктоп — тоже разные ответы.

## Окна приносит приложение

Модуль знает ровно одно своё окно — программу под PTY. Всё остальное объявляет
приложение записью процесса, которая умеет писать в свой `tty`-порт; пометка
`meta.type: tui_desktop.window` кладёт её в меню `alt+o`, а `meta.title`,
`meta.width` и `meta.height` говорят, как её открыть. Ни строчки в этом модуле
править для нового окна не нужно — иначе каждое приложение требовало бы релиза
десктопа.

```yaml
- name: window_calc
  kind: process.lua
  meta:
    type: tui_desktop.window
    title: Калькулятор
    width: 28
    height: 15
  source: file://window_calc.lua
  method: main
  modules: [channel, tty]
```

Такое окно открывает поверхность своего порта и публикует кадры — в отличие от
окна с программой, где аренду порта забирает себе PTY-сессия. Через командный
канал оно открывается по имени записи: `{"entry": "app.desktop:window_calc"}`.

## Окно можно собрать в работающем рантайме

Реестр меняется на живую (`snapshot → changes → apply`), поэтому окно не обязано
быть файлом: его код едет в теле запроса, и окно появляется в меню сразу — без
перезапуска.

```bash
curl -X POST -H 'Content-Type: application/json' \
  -d '{"name":"clock","title":"Часы","width":30,"height":6,
       "modules":["time"],"source":"…lua…"}' \
  http://localhost:8099/api/v1/tui-desktop/apps
```

Исходник при этом ложится в таблицу `butschster_tui_desktop_windows`, и на
старте композитор возвращает сохранённые окна в реестр. Без этого собранное
окно жило бы ровно до конца процесса.

Восстанавливает именно композитор, а не фоновый сервис, и это не выбор стиля:
платформа намеренно запрещает процессам группы `wippy.security:process` менять
реестр — политика `wippy.security:registry.no_write` перекрывает разрешения
явным `deny`, и такой сервис молча не делал бы ничего. Композитор работает под
собственным актором, а нужны эти окна ровно тогда, когда десктоп запущен.

Итог восстановления виден снаружи — `GET /tui-desktop/windows` отдаёт поле
`restore` (`restored`, `failed`, `names`, `error`). Лог терминального хоста
заглушён, иначе он разъедет кадр, поэтому отказ, рассказанный только в лог, не
рассказан никому.

- **Одна строка на окно, имя — ключ.** Повторная сборка перезаписывает: история
  правок не ведётся, а «имя занято» было бы отказом чинить собственное окно.
- **Сборка окна одна на оба пути.** Мастерская и загрузчик строят запись одним
  и тем же кодом — разойдись они, окно вело бы себя по-разному до и после
  перезапуска, а такое расхождение проявляется через сутки.
- **Модули окна выбираются из белого списка**: `channel`, `time`, `tty`,
  `json`, `sql`, `env`; `tty` и `channel` добавляются всегда. Запрошенный
  модуль вне списка — отказ с его именем, а не молчаливое игнорирование.
  Порождать процессы и запускать программы окну нечем: код приходит по HTTP,
  и права выданы ровно под рисование и чтение данных.
- **Удаление не гасит открытые окна.** Процесс живёт своей жизнью; удалена
  возможность открыть новое, и ответ говорит об этом прямо.

## Окно может попросить десктоп

Клики и клавиши доезжают до окна как есть — композитор транслирует их в его
координаты. Обратный путь даёт библиотека `desktop`, которую мастерская
подключает каждому собранному окну:

```lua
local desktop = require("desktop")

desktop.open({entry = "…:dataflow_detail", title = "Узлы", args = flow_id, w = 86, h = 18})
desktop.focus(id)
desktop.close(id)
```

Так виджет становится действующим: клик по строке открывает соседнее окно с
параметром. Окно-приложение получает свой параметр как `args`; `command`
остаётся программой для PTY-окна — одно поле на оба смысла читалось бы как
«команда», и окно подробностей открывали бы строкой `/bin/bash`.

Граница при этом узкая и проверяется тестом: окно умеет **попросить**
(`process.send` и найти адресата), но `spawn`, `exec` и `registry.apply` ему не
выданы. Присланный по HTTP код может дёргать ровно те команды десктопа, что и
так открыты снаружи, — и ничего сверх.

Ответа `desktop.open` не ждёт намеренно: ожидание чужого ответа заморозило бы
кадр окна, а что окно открылось, видно на экране.

## Вид отделён от механики: контракт темы

Композитор — библиотека `butschster.tui_desktop.desktop:library` с одной
функцией `run(options)`. Всё, что рисуется, приходит темой в `options.chrome`;
геометрию хрома — сколько строк занято сверху и снизу — тоже объявляет она.
Штатная оболочка (`…:desktop`) зовёт `run` со своей темой; вторая оболочка
приносит другую и получает другой вид, не копируя ни хостинг окон, ни PTY,
ни командный канал.

```lua
local library = require("library")
local chrome = require("chrome")

local function main()
    -- Голым `return library.run(...)` это писать нельзя: в go-lua v1.5.18
    -- хвостовой вызов yield-функции из базового фрейма корутины не
    -- выполняется вовсе — молча, за 0 мс.
    local ok, err = library.run({chrome = chrome, service_name = "…"})
    return ok, err
end
```

`options`:

| Поле | Смысл |
|---|---|
| `chrome` | тема. Обязательна: композитор без вида — пустой экран, в котором нечего искать, поэтому отказ называет причину, а не подставляет тему молча |
| `service_name` | имя, под которым композитор виден процессам |
| `hint` | подсказка на пустом рабочем столе |
| `catalog` | `() -> items, failure` — каталог программ. По умолчанию внутренний, плоский |
| `desktop_items` | `() -> items, failure` — раскладка стола: ярлыки и папки. По умолчанию пусто |
| `restore` | возвращать ли на старте окна мастерской в реестр; по умолчанию да |

Тема — библиотека, возвращающая таблицу. Композитор зовёт только это:

| Функция | Обязана |
|---|---|
| `layout(width, height)` | вернуть `{top = N, bottom = M}` — сколько строк хром забирает сверху и снизу. Рабочий стол — строки `top + 1 .. height - bottom` |
| `fill(canvas, width, height, state)` | залить рабочий стол и нарисовать значки; вернуть разметку попаданий или ничего |
| `window(canvas, window, focused)` | нарисовать рамку, заголовок и содержимое окна |
| `bars(canvas, width, height, state)` | нарисовать полосы (полоса окон, панель задач, статус) и вернуть разметку попаданий |
| `menu(canvas, width, height, items, failure)` | нарисовать каталог программ и вернуть разметку попаданий |
| `empty_desktop(canvas, width, height, text)` | подсказка на пустом столе |
| `BUTTONS`, `BUTTONS_WIDTH` | таблица кнопок заголовка для хит-теста |

`state` у `bars` — `{windows, focused_id, menu_open, status, clock}`;
у `fill` — `{top, bottom, items, failure}`.

Попадание — запись `{row, from, to, …}` с одним из: `id` (поднять окно),
`index` (пункт меню), `action = "menu"` (открыть или закрыть каталог),
`entry` (открыть программу; на столе — по двойному щелчку).

**Разметка попаданий и отрисовка считаются по одной таблице.** Отдельная
формула для клика однажды разъедется с отрисовкой, и кнопка «закрыть»
окажется на символ левее, чем выглядит. То же про геометрию: пока она была
константой внутри композитора, панель задач снизу требовала правки
композитора — то есть механика снова знала бы про вид.

Тема, попросившая больше строк, чем есть на экране, не роняет композитор:
он сводит геометрию к экрану и рисует. Иначе окна уезжают за край молча.

## Устройство

- `src/desktop/library.lua` — механика композитора: окна в z-порядке, ввод, команды, отрисовка. Вида не знает
- `src/desktop/desktop.lua` — штатная оболочка: выбор темы и имени, больше ничего
- `src/desktop/chrome.lua` — штатная тема: рамки, заголовки, кнопки, полоса окон; чистые строки без вызовов в рантайм
- `src/desktop/window_pty.lua` — окно: отдаёт свой порт настоящей программе под PTY
- `src/api/` — командный канал, мастерская и их политики
- `src/persist/` — хранилище окон, сборка записи реестра и загрузчик
- `src/migrations/` — таблица окон, собранных в рантайме
- `src/security/` — политики: композитору, каналу, мастерской, окнам, доступу

Права разделены нарочно. Композитору нужно порождать процессы и запускать
программы; командному каналу — только найти композитор и заговорить с ним.
Право `spawn` у ручки означало бы, что HTTP-запрос запускает программы мимо
единственного места, которое их считает.

## Разработка

```bash
make setup     # разрешить зависимости модуля и харнесса
make lint      # wippy lint
make test      # автономный харнесс, реестровые проверки
make verify    # всё вместе
```

Харнесс в `test/` подменяет модуль рабочей копией из `..`, поэтому он же
поднимает десктоп без всякого приложения:

```bash
cd test && wippy run --host butschster.tui_desktop:terminal desktop
```

Полноэкранную программу нельзя проверить кодом возврата: без настоящего
терминала она не запускается вовсе, а запущенная пишет не строки, а поток с
абсолютным позиционированием. Пробник [`tools/tui-probe.py`](tools/tui-probe.py)
даёт PTY заданного размера, печатает по сценарию и разбирает поток в текстовую
сетку — снимок экрана и есть доказательство.

```bash
cd test && python3 ../tools/tui-probe.py --cols 100 --rows 26 --boot 60 \
    --send $'\033n' --send 'echo ok' --send-key enter --expect 'ok' \
    -- wippy run --host butschster.tui_desktop:terminal desktop
```

### Две ловушки, стоившие здесь времени

**Хвостовой вызов.** В go-lua v1.5.18 вызов yield-функции, стоящий последним
как `return f(...)`, не выполняется вовсе — молча, за 0 мс, с пустым
результатом. Такую форму имеют все вызовы этого стека: `tty.start`,
`surface:present`, `viewport:send`, `session:send`. Поэтому они обёрнуты в
`assert(...)`: это не стиль, это обход.

**Экран без размера.** Запуск не из терминала (скрипт, CI, пайп) отвечает на
`screen_size()` нулями, и холст такую ширину отвергает — композитор падал на
первой же строке. Геометрия поэтому проверяется, а не берётся на веру.
